## 四、女仆收纳空间

7. **入口**：左上角神龛**右键**打开（左键仍保留原来的猫叫 + 星星粒子）
8. **收纳**：名册每行最左侧新增「收纳」按钮（神龛图标），点一下把该女仆收进去
9. **数据格式与本体魂符一致**：使用 `EntityMaid.saveWithoutId` 保存完整实体 NBT，
   血量 / 好感 / 经验 / 背包 / 模型 / 狐梦成长数据全部保留
10. **与本体魂符的差异**：一个收纳空间可以装**任意多只**（本体一张魂符只能装一只）
11. **收纳后**：实体消失，名册中自动隐藏（不会残留成「未加载」条目）
12. **收纳界面**：
    - 实体**实时渲染小头像**（用收纳时录制的 NBT 重建展示实体）
    - **名字搜索**
    - 逐只「释放」
    - 底部「全部释放」
    - 关闭后**回到女仆名单主界面**（不是直接回游戏）
13. **持久化**：存档级 `SavedData`（`maid_list_storage`）

## 五、收纳数据灾难恢复

14. **本地完整 NBT 备份**：`config/maid_list_storage_backup.json`（Base64 完整实体 NBT）
15. **自动恢复**：每次上线首次打开收纳空间时，对比本地备份与服务端列表，
    把缺失的女仆自动回传恢复（单次上限 32 只，每条最多尝试 3 次）
16. **存档来源校验**：收纳时给数据打签章 `MaidListOrigin{key, sig}`
    - `key` 来自每个存档独有的随机密钥，**单独**存放在 `maid_list_world_key`
    - `sig` 是 `SHA-256(key + ":" + 女仆UUID)`
    - 恢复时服务端重新校验：**来自其它存档 / 被篡改过的数据一律拒绝**
    - 这样多人服务器上无法把自己单机存档的女仆「导入」进服务器
17. 密钥会正常持久化；如果密钥文件缺失但已有带签章的数据，会**从旧数据里继承密钥**，
    避免历史备份全部失效

## 六、仇恨名单管理

18. **入口**：在名册里**右键**任意女仆 → 弹出菜单「为女仆变更仇恨名单」
19. **实体列表**：自动枚举整合包内**所有已注册实体**（含其它模组添加的）
    - 同时显示**中文译名**与**实体 ID**
    - 支持按名称或 ID **搜索**
20. **三态切换**：友好（绿）/ 中立（金）/ 敌对（红）；
    再点一次当前状态即**从名单移除**
21. **批量操作**（底部按钮）：
    - 重置该女仆的名单
    - 复制名单到剪贴板
    - 粘贴名单（剪贴板为空时按钮为禁用态）
    - 将当前名单**同步至全体女仆**
    - **重置所有女仆**的名单
22. **与本体双向同步**：直接读写车万女仆的 `InitTaskData.ATTACK_LIST`
    （`AttackListData` + `MonsterType`），
    与我们面板「任务设置 → 攻击面板」是**同一份数据** —— 任一侧修改，另一侧立刻可见
23. **排序优化**：刚修改过的实体自动排到列表**第一位**（新→旧）；
    **取消修改时保持原位**，不会乱跳
24. **本地留档**：`config/maid_list_attack_backup.json`（按女仆 UUID 归档，便于更新后对照）

## 七、已知边界

- 收纳恢复依赖存档密钥文件；若整个 `data/` 目录丢失（密钥与数据同时没了），无法校验恢复
- 仇恨名单的批量同步只作用于**已加载**的女仆（未加载实体读不到数据）
- 收纳界面小头像依赖实体 NBT 重建，个别模型可能需要额外客户端状态
